# UE5 客户端与服务端联调步骤清单

本文档用于指导 UE5 客户端与当前服务端进行实际联调，目标是从登录到进场景再到基础玩法，完整跑通一条可验证的闭环。

---

# 1. 联调前准备

## 1.1 服务端准备
- [ ] `auth-server` 启动成功
- [ ] `game-server` 启动成功
- [ ] `web-admin` 启动成功（可选）
- [ ] MySQL / MariaDB 已启动
- [ ] Redis 已启动
- [ ] 数据库表已执行 `db/init.sql`
- [ ] `auth-server` 数据源已切换为 MySQL / MariaDB
- [ ] `game-server` 数据源已切换为 MySQL / MariaDB
- [ ] `game-server` Redis 配置正确

## 1.2 客户端准备
- [ ] UE5 工程已创建
- [ ] 网络模块已接入
- [ ] protobuf 库已接入
- [ ] 已生成客户端协议类
- [ ] 蓝图 UI 已准备
- [ ] 登录页已准备
- [ ] 角色选择页已准备
- [ ] HUD 已准备

---

# 2. 登录联调

## 2.1 HTTP 登录
1. 在 UE5 登录 UI 输入账号密码
2. 调用 `POST /api/auth/login`
3. 校验返回的 `token` 和 `userId`
4. 保存到 `GameInstance`
5. 进入角色选择界面

### 验证点
- [ ] HTTP 请求成功
- [ ] Token 有效
- [ ] 登录失败时 UI 提示正确

---

# 3. TCP 连接联调

## 3.1 建立连接
1. UE5 调用 TCP 连接服务端
2. 连接 `game-server`
3. 发送 `1001` 握手包
4. 等待 `1002` 响应

### 验证点
- [ ] Socket 成功连接
- [ ] 握手请求发出
- [ ] 握手响应收到
- [ ] 网络状态切换为 `Authenticated`

---

# 4. 角色联调

## 4.1 请求角色列表
1. 握手成功后请求角色列表
2. 收到角色列表响应
3. 显示角色卡片

### 验证点
- [ ] 列表展示正确
- [ ] 角色名/等级/场景正确

## 4.2 创建角色
1. 输入角色名
2. 发送创建角色请求
3. 收到创建成功响应
4. 刷新角色列表

### 验证点
- [ ] 新角色显示成功
- [ ] 角色名唯一性校验正确

## 4.3 进入角色
1. 选择角色
2. 发送进入角色请求
3. 收到进入成功响应

### 验证点
- [ ] 进入成功
- [ ] 角色上下文正确保存

---

# 5. 场景联调

## 5.1 进入场景
1. 进入角色成功后发送进入场景请求
2. 收到 `4002`

4. 创建玩家角色
5. 创建 HUD
6. 启动同步定时器

### 验证点
- [ ] 地图加载正确

- [ ] 场景实体加载正确

---

# 6. 基础运行联调

## 6.1 心跳
1. 启动心跳定时器
2. 周期发送 `3001`
3. 检查服务端响应

### 验证点
- [ ] 心跳稳定发送
- [ ] 服务端无异常断开

## 6.2 移动
1. 玩家移动时触发移动同步
2. 发送移动包
3. 收到移动/状态响应

### 验证点
- [ ] 移动包发送正常
- [ ] 服务端状态同步正常

## 6.3 聊天
1. 输入聊天内容
2. 发送聊天消息 `7001`
3. 监听 `7003`

### 验证点
- [ ] 聊天消息发送正常
- [ ] 广播显示正常

# 11. 断线重连联调

1. 手动断开网络或关闭服务端
2. 检查客户端是否进入重连状态
3. 重启服务端
4. 检查客户端是否自动重连
5. 检查握手、场景恢复是否正常

### 验证点
- [ ] 断线提示正确
- [ ] 自动重连正确
- [ ] 会话恢复正确

当以下条件满足时，可认为基础联调通过：

- [ ] UE5 成功登录

- [ ] UE5 成功握手
- [ ] UE5 成功获取角色列表
- [ ] UE5 成功创建/进入角色
- [ ] UE5 成功进入场景
- [ ] UE5 心跳稳定
- [ ] UE5 移动同步正常
- [ ] UE5 聊天正常
- [ ] UE5 战斗正常
- [ ] UE5 掉落/拾取正常
- [ ] UE5 任务正常
- [ ] UE5 能断线重连
- [ ] UE5 能恢复会话

# 15. 结论

这份联调步骤清单建议在团队真正开测前逐条执行。只要最小闭环跑通，后续再逐步补齐高级玩法即可。
